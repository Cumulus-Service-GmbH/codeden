11. **Closeout** (last gate before learnings, every tier, every run). Nothing a run created stays open. A run with an open registered worktree cannot reach `finished`. **Clean end state (part of this gate; the learnings gate and `finish` refuse without it).** After closeout run `node "<skill>/scripts/clean-state.mjs" check --repo <main checkout> --run <id>`. A run that produced a task branch ends only when nothing it made exists in one place only: no uncommitted work (closeout parks dirty trees on `trio/wip-*` snapshot refs; that is a defect to resolve, not a place to leave work), nothing unpushed (every task branch tip is on the **live** remote), and nothing unmerged and unaccounted for (every branch with commits beyond the default branch has a pull request that is **merged**, its commit on the live default branch, or **open on the pushed tip** and waiting for the user's approval card). The run is not finished and is never marked finished; gate 11 is not passed or skipped: **never mark finished, never skip gate 11**. ## Harness defects

Record every real harness defect encountered in `.trioharness-direct/runs/<id>/harness-defects.md` in the existing run directory. Initial creation is exclusive and create-only (fail if the file exists; never overwrite). Every defect record, including the first, appends its key and path to the run’s `ledger.md`. For each subsequent defect, the Architect verifies the record file still exists and writes the new record using append mode (for example, `writeFileSync(path, record, { flag: 'a' })`); existing records are never rewritten. Each defect has one level-two heading exactly `## <key>`, with no other heading text. The key is a stable key chosen by the Architect, matching `^[A-Za-z0-9][A-Za-z0-9._-]{0,39}$` and identical to the value passed to `issues.mjs open --key <key>`. Put the display ID, severity, file:line, evidence and suggested fix in the body below that heading. No body line may start with `## `, inside or outside a code fence. The clean-state cross-check validates the entire heading as the issue key.

After the done gate (acceptance) and before ending, only when defects were recorded, the Architect dispatches ONE read-only Investigator per run using `templates/investigator-prompt.md` to compare every recorded defect with the installed version (static inspection). Its sole write is its assigned create-only report under the run’s `workers/` directory; host write scope is that resolved single path, and an existing report makes creation fail. For an accepted run, complete this dispatch before asking any owner-hold card; never dispatch while a blocking card is open. This dispatch counts against the existing invocation budget. With no recorded defects, no such dispatch occurs. The Architect records already-fixed defects as FIXED with evidence; never infer a fix from a version number alone.

Every recorded defect gets an issue through `issues.mjs open` with label `harness-defect`, operated only by the Architect with the verified agent identity, including already-fixed defects with truthful status and evidence. For each STILL-PRESENT defect start a separate fix run in https://github.com/Cumulus-Service-GmbH/trioharness-lean through all existing checks: plan, Plan Reviewer, Writer, guard, tests, Code Reviewer, Jev and PR, followed by the existing acceptance and delivery checks. Installed skill files change only after the owner install card; merge, install and settings decisions remain owner gates.

Self-repair repairs real defects only and never lowers a threshold, marks a gate advisory, resets a gate, or edits a hook to get a run through. The unchanged Jev refusal rule below still applies. A fix that weakens a gate is HIGH. A blocking harness defect leaves the run parked at the failed gate with an owner decision card; it never grants a check exemption or an automatic repair path.
