# Promotion, database and delivery gates

Loaded on demand from the trioharness-lean SKILL.md. Every rule here is binding when its trigger applies; this file only moves text out of the everyday core.

7. Freeze the candidate and run the independent code review below. Commit/push/PR writes require exact session or standing authorization. Agents push only task branches (`codeden/*`, `bambooed/*`, `trio/*`) under the repo AGENTS.md standing authorization; the repository pre-push hook rejects any other ref from agent processes. Merges to the default branch are the user's, except in CodeDen, where the PM or its session merges per SKILL.md gate 9 once this review has no HIGH/MEDIUM and the gates passed. Use LOCAL_PRECOMMIT when policy requires review first or no remote/push authorization exists; do not require an external write just to obtain review.
8. Before promotion, check the exact target database using `dotnet ef migrations list --context <DbContext> --configuration Release --no-build` without printing connection strings. Pending migrations, an ambiguous target, or unknown DB state block promotion.
9. A pending migration requires separate explicit authorization naming the target DB and migrations. Generate/inspect exact idempotent SQL; record table/index/history preconditions; apply only that batch; verify schema, __EFMigrationsHistory, and no pending migrations. Never update to an older migration when later migrations are applied.
10. For container/VM/cloud delivery, complete [promotion-rehearsal.md](references/promotion-rehearsal.md) and pass its receipt to `--promotion-check true`. Before any deploy, read the running commit SHA from the live app's version/health endpoint or image tag and prove `git merge-base --is-ancestor <live-sha> <candidate>`; a live SHA absent from the remote means unpublished code was deployed — stop and report. State target/ref/SHA/mutations/DB/rollback and obtain exact authorization. Deploy a clean reviewed commit; use bounded readiness, verify runtime identity/health/logs, and reconcile canonical refs without force.

A clean local precommit review stays pending until the exact reviewed candidate is committed with authorization. Revalidate the existing receipt against unchanged content to write its promotion lock; do not buy another review for an identical commit. Promotion additionally requires green current verification, no unresolved confirmed/probable High/Medium, reviewed content, rehearsal where applicable, and explicit authorization.
