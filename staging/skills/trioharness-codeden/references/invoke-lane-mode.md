# invoke-lane mode (enforced isolation, launcher receipts, promotion locks)

Loaded on demand from the trioharness-lean SKILL.md. Every rule here is binding when its trigger applies; this file only moves text out of the everyday core.

**Model-agnostic use:** reviewer models and efforts come from `~/.config/trioharness/team.json` (drift-checked with `team-sync.mjs --check` at launch); `--review-model <id> --review-effort <level>` may only repeat them, anything else is refused (`TEAM_MODEL_MISMATCH`); add `--review-engine gpt` when the reviewer runs on Codex (read-only, MCP-free, user-config-free sandbox). Contracts, markers, receipts, revalidation and promotion locks are identical for every model. The receipt records `modelEvidence`; when Codex reports no model field it is `requested-only`. The launcher has **no built-in reviewer models**: without team.json the review roles refuse to start.

**CodeDen Team pins** (team.json; invoke-lane reads them itself): plan reviewer `--role reviewer-plan --review-engine gpt` runs `<team:planReviewer.model>`/`<team:planReviewer.effort>`; code reviewer of Claude-written code `--role reviewer --review-engine gpt` runs `<team:codeReviewer.fallback.claude>`; of Codex-written code `--role reviewer` runs `<team:codeReviewer.fallback.codex>`. invoke-lane cannot run the primary Code Reviewer `<team:codeReviewer.primary>` (agy), so its code reviews are always the fallback route, recorded with `--review-slot fallback|second-pass --fallback-reason <text>` (default reason: invoke-lane cannot run the primary); the primary runs through the skill's `team-review.mjs`. The `executor-sol`, `explorer` and `planner` lanes run `<team:writer.model>`. Without `headroom`, use `SKILL.md` **Pinned Codex commands**.

Use this mode when a task needs enforced writer isolation (untrusted input, credential-bearing areas, override-level diffs) or when promotion-bound work needs a launcher review receipt and promotion lock.

## Roles and launch

- Coordinator: active user-selected Codex model. Recommend **GPT-6 Astra medium** for routine coordination, high for consequential planning/arbitration. It owns requirements, scope, dispositions, integration, and final acceptance. Do not claim to switch a session's model/effort unless actually configured.
- Primary writer: **QwenCloud Direct `qwencloud/qwen3.8-flash`** through local OpenCode. Require `QWENCLOUD_API_KEY`, `QWENCLOUD_BASE_URL`, `OPENCODE_CONFIG=~/.config/opencode/qwen-worker.json`, and `opencode --pure`; use `qwen-worktree-worker` so the writer receives a fresh isolated worktree and only OpenCode's built-in file, shell, Git-inspection, and local-test tools. The configuration must contain one provider and must deny skills, task/subagents, web tools, external directories, deployment commands, and remote/destructive Git commands. Deny mutating `git merge` while explicitly allowing read-only `git merge-base`; do not use a broad deny without the corresponding safe inspection exception. Never load a project `.env`, print the key, or route through OpenCode Go/Zen, OpenRouter, Azure, MCP, plugins, or browser tools.
- Qwen scope safety is fail-closed. Every non-validation Qwen packet must include exactly one single-line `QWEN_APPROVED_OWNED_PATHS_JSON: ["repo/relative/file", "repo/relative/directory/"]` declaration containing the smallest owned paths. The wrapper rejects malformed, absolute, parent-traversing, wildcard, empty, or undeclared paths and pins its comparison base before launching the worker. Explicitly forbid repairing test, hash, toolchain, or checkout failures through repository-wide line-ending, encoding, formatter, generated-file, asset, or binary normalization; the writer must report baseline/environment failures instead. Before accepting a Qwen commit, require a clean worktree and inspect the complete path list plus diff statistics. `qwen-worktree-worker` rejects any changed path outside the declared ownership, more than 32 changed files, more than 20,000 added+deleted lines, or any binary change unless the independently reviewed packet includes the exact applicable override `QWEN_LARGE_DIFF_APPROVED: true` or `QWEN_BINARY_CHANGES_APPROVED: true`. An override never permits a path outside `QWEN_APPROVED_OWNED_PATHS_JSON`. A rejected lane remains isolated and must never be cherry-picked, merged, reviewed as a candidate, or promoted.
- Writer fallback: **gpt-5.6-terra medium** through the existing isolated `executor-terra` lane. Use it only when QwenCloud fails before useful authoring begins because the required environment, provider, authentication, endpoint, or OpenCode runtime is unavailable. Record the exact pre-start failure and announce the fallback; never silently replace Qwen after a model-quality, test, or implementation failure.
- Initial plan reviewer: team.json's Plan Reviewer (`<team:planReviewer>`), exactly once. Code reviewer: team.json's writer-specific Code Reviewer fallback (`<team:codeReviewer.fallback.<writer>>`). New reviews must launch these exact models and fail runtime verification on a different reported model or effort; no silent substitution. Existing reviews remain bound to their original installed launcher and evidence, including revalidation. Legacy role/header/receipt names remain readable.
- Claude uses the existing local subscription. Require CLI >=2.1.170 and verified model/authentication/isolation. Never configure ANTHROPIC_API_KEY. The launcher uses Headroom, safe mode, strict MCP isolation, empty setting sources, disabled slash commands, `stream-json --verbose`, no persistence, and the inspection tools Read/Glob/Grep/Bash/PowerShell. Never add token-fragment streaming. Only a successful terminal result is a review; banners and echoed prompts are not evidence.
- Keep receipts outside the frozen checkout. Headroom runs in a per-receipt runtime directory with Claude `--add-dir` access to that checkout; its generated settings must not dirty reviewed source. Revalidation requires the original transcript hash as well as unchanged packet, context, source bytes, and modes.
- Model IDs live only in team.json; verify them against the provider's model documentation (for Claude, [Anthropic model configuration](https://code.claude.com/docs/en/model-config)) before changing team.json; mock fixtures do not establish provider availability.
- Require actual structured init/result records: expected model, `apiKeySource: none`, empty MCP servers, and no reported active customizations. Launch arguments establish requested effort when the runtime omits it; any contradictory runtime report fails. Missing or unverified evidence is INCOMPLETE, never CLEAN.

On Windows, invoke `node "<absolute-skill-path>/scripts/invoke-lane.mjs" ...` directly from PowerShell with no PTY/TTY or outer shell/Start-Process wrapper. Quote absolute paths as separate arguments. Retry a proven pre-start CreateProcessW/PTY failure once with the identical non-PTY command and same receipt. Use native argv or file-backed JSON for CLI payloads; never interpolate secrets or hand paths between shells. Force UTF-8 at every model-process boundary (`PYTHONUTF8=1`, `PYTHONIOENCODING=utf-8`, UTF-8 PowerShell/Node streams) so Unicode findings cannot fail under Windows CP1252.
Qwen shell packets on Windows must explicitly require PowerShell-native commands and forbid assumptions that Unix utilities such as `head`, `tail`, `grep`, `cat`, `rm`, `cp`, or `mv` exist. A failed convenience inspection is not a product failure and must not trigger source edits.
Require Qwen to keep any temporary inspection output in a disposable `.qwen-scratch` directory inside its assigned worktree and remove it before commit. External-directory denial remains absolute; never relax it to accommodate scratch files.

Before each model launch, dry-run the same packet/arguments with `--dry-run true`. Require `packetValidation.status: passed` and review `sourceEvidenceVerified: true`. Correct the full diagnostic list together. Dry-run preserves live receipts/context and uses a sidecar if output exists.

Announce each lane's purpose, worktree/SHA, and receipt. Poll `--status true --output <receipt>` at least every 60 seconds; preserve 15-second heartbeats through verification. Child completion is not lane completion. Review hard cap is 60 elapsed minutes from launcher UTC start, not an idle timer; silence is no reason to kill a reviewer.

## Scope-locked packets

All machine JSON headers are single-line JSON. Standard writer packets declare frozen SHA, `EXECUTOR_SCOPE_LOCK: APPROVED`, task IDs, exact approved owned/no-touch paths, handoff and caller closure, `EXECUTOR_PROTECTED_BEHAVIORS_JSON`, `EXECUTOR_REQUIRED_GATES_JSON`, and INITIAL/DELTA correction mode. Each accepted item has callers, dependencies, risks, invariant, minimal correction, and deterministic proof.

The retired executor orientation, worktree sync, and LSP options refuse before launch when enabled. The coordinator builds the pre-packet caller inventory with `rg` and `git grep`.

Terra telemetry retains its usage counts but marks its cost as `unpriced` with `costUsd: null` until an official provider rate is configured. Do not substitute a blank value with zero or include Terra in the A3.5 cost-per-completed-lane comparison; that comparison is Sol medium versus Sol high only.

`DIRECT_FASTPATH_EXECUTOR_CONTRACT=1` activates only a packet that explicitly declares `EXECUTOR_FASTPATH_CONTRACT: APPROVED` and a 1–24 line maximum. It is a separate, narrow writer contract for mechanical fixes. It retains frozen HEAD, clean-worktree, protected-evidence, authorized-path, gate, and scope checks while requiring only the changed path, focused proof, and scope confirmation in final prose. Do not use it to weaken or replace the standard executor contract.

After initial inventory, corrections are DELTA against the immediately preceding candidate, never rebuilt from the clean base. Declare immutable external baseline, allowed delta, and preserved paths; or use explicitly approved in-place delta. The launcher verifies HEAD, unaccounted prior changes, preserved bytes, result IDs, and allowed changed/untracked paths. Writers cannot silently add dependencies/migrations/boundaries or change HEAD.

Review packets declare `FROZEN_SOURCE_SHA`, target/mode, `REVIEW_PROTECTED_BEHAVIORS_JSON`, `REVIEW_KNOWN_FINDING_IDS_JSON`, `REVIEW_CHANGED_PATHS_JSON`, `REVIEW_IMPACT_MAP_JSON`, and `REVIEW_CORRECTION_MODE`. Every known ID maps to nonempty callers/consumers/dependencies/tests arrays of `repo-relative/path::existing literal token`, plus an invariant. No prose placeholders, guessed future symbols, or stale tokens.

Reconciliation also names `REVIEW_BASELINE_WORKTREE`, `REVIEW_BASELINE_SHA`, and `REVIEW_CORRECTION_DELTA_PATHS_JSON`. Context and candidate contents are immutable. Revalidation checks original evidence; filenames alone cannot transfer review approval to changed bytes. Preserve incomplete/legacy evidence rather than calling it fresh.

Dirty LOCAL_PRECOMMIT reconciliation additionally pins an external `REVIEW_PREDECESSOR_MANIFEST` with `REVIEW_PREDECESSOR_MANIFEST_SHA256`. Its schema-1 JSON declares the frozen base and complete sorted file records (path/state/Git mode/blob ID/raw hash/base64 bytes); preserve the actual predecessor through revalidation. The launcher retains full schema-2 snapshots durably, but sends only compact identities and the complete correction diff to the model. Inputs over 256 KiB fail before launch; reduce real scope with approval, never truncate evidence. Existing completed reviews retain their run counts; legacy receipts without transcript identity cannot be silently upgraded into promotion approval.

Known IDs need explicit disposition. Optional `REVIEW_KNOWN_FINDING_COVERAGE_JSON` may link every ID to nonempty declared protected-behavior IDs, only when all linked behaviors and correction paths are explicitly dispositioned. Compact whole-delta coverage must name the exact path count; it cannot hide incomplete/regressed evidence.

## Receipts, revalidation and promotion locks

Run Fable 5.1 on each frozen candidate and preserve every receipt in `CODE_REVIEW_ROUNDS.jsonl`. At most two reviewer calls per candidate (one full + one delta); unresolved findings park the run with their IDs and evidence. See `convergence-and-gates.md`; deterministic revalidation consumes no reviewer call. Revalidation launches no model and remains bound to the original packet, transcript, and candidate.

Closure evidence uses persisted obligations outside bounded history. To bind a named dispatch, pass the same `--worker <id>` to `run-state.mjs dispatch` and `invoke-lane.mjs`; when several named dispatches await launch, the worker is required. Alternatively, supply the same `--review-reservation <id>` to both commands. API registrations made after launch identify it with `registerWorker(..., { id, role, reviewReservation })`. Receipts match that exact reservation; receipts without one match only legacy obligations, once each. A receipt and its markdown output count once. A proven pre-model refund closes its obligation and restores budget; a retry gets a new reservation. Preserve the obligation records even after their history events roll over.

Close a specific obligation with `node "<skill>/scripts/run-state.mjs" worker-done --repo <coordinator-repo> --run <id> (--worker <id> | --review-reservation <id>) --status done|failed|stopped [--report <path>]`. `done` requires an existing, nonempty report; its absolute `reportPath`, SHA-256 and byte size are recorded on that obligation. Audit checks only that recorded path and unchanged, nonempty bytes. Receipts close their reservation by ID; explicit failed/stopped dispositions need no report. Unlaunched reserved dispatches support the same explicit report binding. Unbound files, names, case variants, roles, timestamps and directory counts supply no evidence. Legacy obligations without this contract may omit `--report` only when `workers/<workerId>.md` exists with exact case and nonempty bytes at disposition time; that call records its hash. Ambiguous legacy terminal review ownership requires `worker-done --review-reservation <id>`; a single dispatch, launch and worker or an explicit reservation can establish ownership without clock ordering.

Retries get a fresh obligation and require a fresh disposition. Re-dispatch a failed or stopped worker with a **fresh worker id**, using that same new id in PandaCode and `run-state.mjs dispatch --worker <id>`; reusing the old id refuses with `DISPATCH_ALREADY_RECORDED`. Old report records cannot satisfy it. Registration and relaunch never move any report or sidecar, including late registration. Preserve older bound report paths and bytes if they still supply closure evidence. Refunds clear the matching worker reservation before relaunch. New transcript monitors persist the original reservation alongside the transcript hash. Revalidation repairs a completed receipt only when that original reservation and output both match a persisted, nonrefunded obligation. Unknown original identity leaves the ledger unchanged; an older transcript never binds to a newer same-output reservation. Correct receipts are not duplicated.

Freeze one authorized PR's SHA, blobs, diff, impact map, and ledger, or name LOCAL_PRECOMMIT plus FROZEN_LOCAL_ARTIFACT. PR inventory uses the verified base merge point; local inventory uses its explicit frozen base. Never accept an empty self-diff. Fetch a missing PR base and report incomplete until resolved.
A clean local precommit review stays pending until the exact reviewed candidate is committed with authorization. Revalidate the existing receipt against unchanged content to write its promotion lock; do not buy another review for an identical commit. Promotion additionally requires green current verification, no unresolved confirmed/probable High/Medium, reviewed content, rehearsal where applicable, and explicit authorization.
Preserve logs and evidence for operational failures; never turn them into clean reviews. Diagnose/retry the exact failed deterministic gate within scope. After any terminal verification or readiness failure, immediately present a scoped remediation packet: failed command and evidence, affected owned/no-touch paths, protected behavior, focused RED/retry proof, and whether a new review is required. A transport process may exit nonzero after emitting a complete successful structured review; accept that artifact only when its terminal result, required markers, model, effort, authentication/isolation, prompt/context hashes, and candidate bytes all verify, and record the process exit separately. Timeouts, error results, malformed output, missing runtime proof, or changed bytes remain INCOMPLETE. Keep recoverable dirty worktrees. Remove only the run's verified clean temporary artifacts after terminal success. Handoff exact commands/results, remaining limitations, and the achieved objective.
