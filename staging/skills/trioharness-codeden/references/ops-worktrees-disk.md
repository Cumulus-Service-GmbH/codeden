0. **Repository shape** (before anything else, every run). `node "<skill>/scripts/repo-shape.mjs" --repo <repo> --remote origin --want main`. Gate 1 bases the candidate on `origin/<default>` and the pre-push hook protects that ref, so a repository with no default branch, or whose remote default is a task branch (`bambooed/*`, `trio/*`, a dated slice such as `harnessloop20260921`), cannot be based, guarded or merged correctly. The script asks the **live** remote (`ls-remote`), never cached refs. Exit 0 proceeds — and if it prints `default branch: master …`, that is the default: base on it and pass `--want master` from now on. Exit 2 means the shape must be repaired first, and the script prints the exact fix:
   - `task-shaped-default` or `no-default-branch` → **the Architect repairs it itself** with `repo-shape.mjs --apply`. The repair is bounded to: fetch the source branch *from the remote* and create `main` from `FETCH_HEAD` (never from local `HEAD`, a local branch or a cached tracking ref, so nothing unpushed can become the default), push it as a ref **creation** (the pre-push hook admits that one creation under the marker the script sets and blocks every update of `main`), set the local remote head, and `gh repo edit --repo <this remote's URL> --default-branch main` (GitHub remotes only). It never deletes, moves or rewrites a branch, and rerunning it resumes at the first step not yet done. It runs only when the repo AGENTS.md carries, verbatim, the standing-authorization line the script prints (bootstrap writes it from `templates/repo/AGENTS.md`); without it the script refuses and the Architect asks the user once, showing the printed commands.
   - `SHAPE_PARTIAL` (branch created and pushed; remote default not settable — no `gh`, no permission, or a non-GitHub host) → record it, tell the user the one setting to change, and continue: `main` now exists, so gate 1 can base on it.
   - `SHAPE_FAILED` at the push → the hook or the remote refused. Report the reason verbatim and stop; **never** `--no-verify`, never edit, disable or relocate a hook, never change `core.hooksPath`, and **never set `TRIOHARNESS_SHAPE_CREATE` yourself** — only `repo-shape.mjs` sets it, for its own child processes.
   - `local-branch-conflict` → a local branch already carries the default's name and is not the remote source head. The harness never pushes or moves a branch it did not create: ask the user.
   - `empty-repo`, `no-remote`, `no-remote-source` (no remote branch to cut the default from) or `remote-unreachable` → never automatic. Ask the user (an initial commit, a remote, or the choice of source branch are theirs), and meanwhile record provenance per gate 1's local-only rule.
   Record the verdict and any repair in the ledger. A repaired shape is re-checked with the audit command, not assumed.
0b. **Running ref** (every run, right after gate 0). The base is `origin/<default>`, but QA or production may run code that is not on it (an unmerged branch put there by hand, a hotfix, a build from a deleted branch); work cut from the default branch would silently drop it. `node "<skill>/scripts/running-ref.mjs" check --repo <main checkout> --run <id>` reads what every environment the repo declares really runs (`.trioharness/environments.json`: names, public health URL and SHA field, no secrets; plus the `health` blocks of `deploy.json`) and compares it with the freshly fetched default branch. Per environment: `same`, `behind` (the default moved on: normal), `unverified` (no usable SHA reported: a warning that goes into the final report; adding a version endpoint is its own task), or the two blocking verdicts `unmerged` (the running commit is not on the default branch) and `unknown-commit` (it is on no branch of this repository). Exit 0 continues. Exit 2: `running-ref.mjs card --run <id>` → `questions.mjs ask` → end the turn; after the answer run `running-ref.mjs resolve --run <id> --set Q-<n>`. The three fixed answers: base on the default branch and leave that environment alone (recommended; the deploy guard then refuses to deploy over it), stop (a separate task brings that code into the repository), or base on the default branch and accept that a later deploy replaces it. In a repo that declares environments the base gate cannot pass until the check is recorded and any blocking drift is answered (`RUNNING_REF_UNRESOLVED`); a repo that declares none is `not-configured` and bootstrap proposes declaring them. Independently, `deploy.mjs` refuses `WOULD_OVERWRITE_UNMERGED` whenever the target runs code that is not part of the SHA being deployed; only a person with `--allow-overwrite <first 12 of the running SHA>`, or an agent holding the recorded "accept replacing it" answer for that target and commit, may override it. It also refuses `RUNNING_REF_UNREADABLE` when it cannot read what the target runs (an agent stops and asks the user; a person passes `--allow-unreadable <target>`), and it reads `deploy.json` from the default branch only (`references/deploy.md`, Deploy guards).

The running-ref check resolves origin's default branch and SHA with `git ls-remote --symref origin HEAD`, verifies a fresh fetch against that SHA, and reads both manifests from it. Target names and deploy app names are classified against `~/.config/trioharness/azure-targets.json` as prd, nonprd, conflict, or unknown. A selected check must probe only nonprd and omit only prd, and the base gate repeats those checks. Probes that share a prd hostname are refused, including when ports or paths differ, except for a full check's own declared prd or conflict probes. The full check still uses read-only GETs for every declared target and logs each prd probe. Prd and conflict probes may only GET `/health`, `/api/health`, or `/build-info` with no query string or fragment, and the CLI refuses `--include-prod`. Receipts are signed for the repo and run ID using `~/.config/trioharness/running-ref.key`.

1. **Base, ledger and checkpoints.** Checkpoint every gate with `scripts/run-state.mjs` (see the continuity reference); on resume, continue at its `resumeAt`. `git fetch`; the base is the fetched `origin/<default>` SHA, never local `main`. Run the `pre-worktree` reclaim (see Disk discipline) **before** cutting the tree, and `closeout.mjs audit --repo <main checkout>` too: if it lists more than 6 open worktrees (or any `--strict` problem), close the stale ones first (`closeout.mjs close --scope stale`, see Worktree closeout), subject to the owner-hold disposition: withheld `--apply` actions do not run; use audit-only commands and blocked closeout instead — never pile a new tree on top of a mess. **Every worktree the run creates — writer, reviewer, scratch or slice — is registered the moment it exists:** `run-state.mjs worktree --repo <main checkout> --run <id> --path <wt> --branch <b> --role writer|reviewer|scratch|slice`. **Fewer trees, smaller trees (before any `git worktree add`):** (i) `node "<skill>/scripts/treespace.mjs" room --repo <main checkout> --path <planned tree path>` (measures the drive the tree will live on, writable space only) — exit 2 means under 20 GB free (or unmeasurable): close or reuse a tree, never cut another; `--min-free-gb` changes the limit. (ii) **Reuse before cutting:** after step (b) below, `treespace.mjs reuse --repo <main checkout> --run <id> --base <base-sha> --apply` re-points an idle tree to this run's new branch (old branch untouched, tree registered). Isolation holds because a tree qualifies only when it is clean, fully on the live remote, unlocked (run-lock and `git worktree lock`), not registered to any unfinished run, free of earlier run records, not sparse, untouched for 2 hours and not your own folder — and ownership is re-checked under the lock, so two runs can never get the same tree; it refuses a switch that would overwrite a git-ignored local file. It reports `no idle clean harness tree to reuse` when none qualifies, and only then is a new tree cut. (iii) **Reviewers and the browser tester get no worktree:** they read the diff packet (`git diff <base>..<head>` saved as `runs/<id>/proof/review-<n>.diff`, never under `tmp/`, with its sha256 recorded in the ledger so the reviewer can verify it was not altered after freeze) — register a reviewer tree only when the review must run tests, and close it right after. (iv) **Seed dependencies without copying them:** in a new tree, `treespace.mjs seed --from <existing tree> --to <new tree> --apply` clones git-ignored `node_modules` by copy-on-write into a private folder and renames it into place (Linux btrfs/XFS reflink; macOS `cp -c` on the same volume, verified by free-space delta — a full copy is deleted and reported; Windows and any other filesystem copy nothing, you install normally). A full copy is never kept. On a Mac where it reports cannot-clone, prefer pnpm, which shares packages through its own store. Run it before the writer starts installing, never while an install is running in that tree. Build caches (`bin/`, `obj/`, `.vite`) are never seeded. Accepted checkpoint names: `shape`, `base`, `route`, `task-card`, `plan-review`, `plan-jev`, `build`, `guard-proof`, `review`, `low-fold`, `done-jev`, `commit-push`, `deploy-qa`, `browser-test`, `closeout`, `learnings`. Record gate 0 with `run-state.mjs set --run <id> --gate shape --status passed`. This records the checkpoint; it does not enforce gate order.

**Cutting a tree is live-base enforced, in this order:** (a) `git fetch <remote> <default>`; (b) read the base as `git rev-parse <remote>/<default>` — never local `main`, never a SHA cached from an earlier gate or a handover; (c) create the run's own branch at that SHA, and only ever a branch the harness itself creates: in a fresh tree `git worktree add -b bambooed/<run-id> <path> <base-sha>`; inside a worktree Bambooed already provided, `git checkout -b bambooed/<run-id> <base-sha>` — never `reset --hard`, `branch -f` or `checkout -B` on a branch you did not create, and never touch the user's checkout or dirty work. A tree Bambooed provided is registered like any other (`run-state.mjs worktree --repo <main checkout> --run <id> --path <tree> --branch bambooed/<run-id>`): only registered trees, or trees under a `.trioharness` root, are ever reused, reclaimed or closed by stale scope, and never one that changed in the last 2 hours; (d) prove it with `node "<skill>/scripts/guard.mjs" --base <base-sha> --remote <remote>/<default> --max-behind 0 --owned '<owned JSON>' --tier <tier>`, which asks the live remote again — `remote-ref-stale` or `base-stale` means the remote moved between fetch and cut, so refetch and cut again; `remote-unverified` means the remote cannot be asked, and an unverified base is never used. Record the base SHA, the branch and the worktree path in the ledger; every later gate reuses that recorded SHA, and `baseBehindRemote` from each guard run is recorded as the run's drift. Record objective, decisions and evidence in `.trioharness-direct/runs/<run-id>/ledger.md` (name kept for launcher compatibility) plus `failures.md`. Local-only source without a remote: record provenance, use an isolated snapshot, never fake remote verification.

## Parallel runs: isolation and drift

The ref policy activates only through environment markers controlled by the caller: unsetting them, `env -i`, a fresh shell, `--no-verify`, `core.hooksPath`, or a hook edit bypasses it. Agents remain forbidden to use these bypasses. Default-ref verification proves the remote advertisement at check time; the remote can move later. The backstop is a server-side ruleset plus separate agent credentials, owned by the user and outside this repository.

Several tasks, workers and sessions share one repository on one disk. Four mechanisms keep them from overwriting each other, and each is enforced by a script, not by convention:

- **One branch per worktree, cut by the harness.** Every tree is created with `-b bambooed/<run-id>` at the recorded base SHA. Git refuses to check the same branch out twice, so two runs cannot share a branch; `guard.mjs` refuses the main checkout (`main-worktree`), so no run can write where the user works. **Run ids** are generated once per objective as `<yyyymmdd>-<slug>-<4 random hex>` in lowercase (letters, digits, `.`, `_`, `-`), so they are unique across machines and safe on case-insensitive file systems; if `bambooed/<run-id>` already exists on the remote, pick another id instead of fast-forwarding onto it. **The ledger is the main checkout's** `.trioharness-direct` (pass `--repo <main checkout>` to every script, worktree registration included), never a linked tree, so one run has one state. **Pushes are fast-forward only**: the pre-push hook refuses a force push or a rewrite of a remote task branch, and refuses every ref outside `bambooed/*` and `trio/*` for an agent shell (the hook is per clone: bootstrap installs it again in every clone, and an agent never passes `--no-verify` or changes `core.hooksPath`). The hook is a guard rail, not the control: the default branch needs a server-side ruleset (no direct pushes, pull request required) because `gh pr merge`, `gh api` and a fresh clone bypass any local hook. Concurrent runs must own disjoint paths (compare the owned-path lists in the ledgers before dispatch; overlap is a question card), and at most three runs per repository work at once.
- **Disjoint owned paths.** Independent work is split only when its owned paths are disjoint (gate 3), and `guard.mjs` rejects any change outside them (`outside-owned-paths`). Two parallel runs that would touch the same file are not parallel work — sequence them, or make one of them a slice of the other.
- **Live base, and drift reported every time.** The base is always the freshly fetched `<remote>/<default>` (gate 1, `--max-behind 0` at cut time); what QA and production run is compared the same way (gate 0b). After that the remote may legitimately move: every verified guard result records `baseBehindRemote` (offline or stale tracking is refused before a result is returned), ancestry is hard-enforced (`base-not-on-remote`), and **before the push in gate 9** refetch and rerun guard — drift there is resolved by rebasing (never pushed yet) or merging the default branch into the task branch (already pushed), then rerunning proof and, if behaviour changed, review. Pushes are per-branch and non-fast-forward rejections are left to fail loudly: never `--force`, never `--force-with-lease`, never `--no-verify`, never a merge or a rebase of someone else's branch.
- **Serialized commands and files.** Every build or test goes through `run-lock.mjs`, which serializes on the worktree and on any `--name <resource>` (a fixed port, a local database, a shared log). Each run writes only under its own `.trioharness-direct/runs/<run-id>/`, so ledgers, worker results and temp output never collide. Reclaim honours the same locks (below). Never kill a process you did not start; exit 75 is a transient lock timeout — wait and retry.

What is **not** protected automatically, and so needs the user: two runs deliberately given overlapping owned paths; a branch rewritten outside the harness; and a candidate whose rebase would change reviewed behaviour (that is a new review, not a merge).

## Worktree closeout (nothing stays open, nothing is lost)

Worktree registration refuses a path already registered to another unfinished run in the same ledger and names that run. Closeout ownership and the boundary's checkout-local run scan follow links to run directories and ignore existing non-directory entries such as `.DS_Store` and `.current-*`. Stat errors, including dangling links, still block ownership checks.

For an unfinished, non-audit run, confirm the branch disposition and ask a card in that run. Put the exact recorded path in backticks in the question and give the Release option the ID `release`. The owner must select it via card, UI or numbered reply. Use a fresh card for each release. Run `run-state.mjs worktree --release --repo <main checkout> --run <id> --path <wt> --card Q-<n>` when the path is absent on disk and from that repository's Git worktree list and the registered branch ref exists locally. Release the registration before deleting its branch because the registered branch must exist locally in the ledger repository. The command removes this run's matching registration and records the path, branch, card, absence evidence and checked repository in its history. Parked runs are eligible. Repeat for each affected run, then run `clean-state.mjs check` and `run-state.mjs finish` for each.

Several worktrees per task and several repositories at once is normal; leaving them behind is not. Every tree a run creates is registered (gate 1) and closed by `scripts/closeout.mjs` (gate 11). For each registered tree it does, in order, and stops at the first thing it cannot prove safe:

1. **Uncommitted work** (modified, staged, untracked) is committed to a snapshot ref `trio/wip-<branch>-<yyyymmdd>-<sha7>` built with a temporary index — the working tree, the real index and the branch are not touched — and pushed (that name is allowed by the agent hook). It refuses, and keeps the tree, if a secret-shaped added line, a secret file name (`.env`, keys) or a file over 20 MB would be committed; values are never printed.
2. **Unpushed commits** on a task branch (`codeden/*`, `bambooed/*`, `trio/*`) are pushed with `--push`. On any other branch the harness may not push: that is a blocker for the user (or `--local-ok` when the user says the commits may stay local). A detached HEAD whose commits are not on the remote is pinned on a `trio/wip-*` ref first.
3. **Local-only ignored files** (e.g. `appsettings.Local.json`, not build output) are copied to `<main>/.trioharness-direct/archive/<branch>/<tree>/ignored-files/` (cap 50 MB; over the cap keeps the tree), and run ledgers are archived with `reclaim`'s `archiveRuns`.
4. The tree is removed with `git worktree remove` (never `--force` unless step 1 preserved the dirt), then `git worktree prune`. A tree whose folder is already gone is only pruned.

It never touches the main checkout, a tree another run owns (run scope = registered trees only; `--scope stale` = idle harness-made trees that no unfinished run has registered), or a held run-lock; it blocks on a nested repository, a rebase/merge/cherry-pick in progress, a data-dump file (csv, xlsx, sql, bak, dump, …), a snapshot over 50 MB, and run files it cannot archive safely; it treats a commit as pushed only when the **live** remote has it; it scans file bytes (UTF-16 and NUL-bearing included) for secrets; it re-checks the tree right before a forced removal and stops if anything changed after the snapshot; a registered tree that belongs to another repository counts as open;  it never deletes a branch, tag or stash, never force-pushes, never bypasses a push hook (the snapshot commit itself is plumbing, so a repo's pre-commit hooks do not run on it; the pre-push hook and the secret scan do). Dry run unless `--apply`; exit 2 if anything stays open. A push that GitHub rejects for a detected secret is never cleared through GitHub's "allow this secret" link: redact locally and re-snapshot; ruleset or signature rejections go to the user with the exact setting. Branches survive closeout — merging or deleting them remains the user's decision at gate 10 / promotion.

**Reviewer and slice trees** are closed as soon as their result is recorded (after the review verdict or after the slice is pushed/merged into the task branch), not at the end — with `closeout.mjs close --repo <main checkout> --run <id> --path <that tree> --apply` (a `--path` close never marks the run's closeout gate passed; only a full `--run` close does). **Several repositories:** one run id per repository; close each with its own `--repo`; `closeout.mjs audit --root <Projects folder>` lists every repository's open trees and `--strict` fails if any is dirty/unpushed or more than 6 are open. Run it at the start of a session and whenever the user asks for a clean-up; it also reports free disk (`--min-free-gb`, default 20) and `--strict` fails on low disk or an unreadable repository (low disk: free space or reuse a tree; it is not a reason to close trees). **Weekly watch:** a scheduled or bot run of `closeout.mjs audit --root <Projects folder> --strict` reports every dirty, unpushed, over-limit or low-disk repository so nothing sits unnoticed; the watch only reports — closing is done in a task, never by the watch.

## Disk discipline (automatic, archive before reclaim)

Runs accumulate worktrees, build output and `node_modules` copies faster than anything else on the host, so reclaiming is part of the workflow, not a chore the user runs later. `reclaim.mjs` archives first and deletes only what it can prove regenerable, and it is run at exactly two points — with `--apply`, no question asked, because nothing unique can be lost, **unless the owner-preservation disposition above applies**. An owner-hold forbids the corresponding `--apply` actions; use audit-only commands and blocked closeout instead:

| When | Command | Takes |
|---|---|---|
| **Before creating a worktree** (gate 1, before `git worktree add`; audit-only during owner-hold) | `node "<skill>/scripts/reclaim.mjs" --phase pre-worktree --repo <main checkout> --worktree <current, if any> --apply` | archives every finished run in every worktree; reclaims caches, run scratch and `node_modules` in idle, unlocked worktrees; clears stale locks |
| **After every successful push** (gate 9, right after `git push`; audit-only during owner-hold) | `node "<skill>/scripts/reclaim.mjs" --phase post-push --repo <main checkout> --worktree <this worktree> --apply` | archives this worktree's runs; reclaims caches and run scratch here, and in other worktrees only when they are idle and unlocked |

- **Archive, then reclaim.** Each run's ledger, `failures.md`, `state.json`, worker results, **`proof/` and `logs/`** (write verbatim proof output there, never under `tmp/`), task card, plan, review rounds and handover are copied to `<main checkout>/.trioharness-direct/archive/<branch>/<run-id>/` **before** anything is deleted, so a worktree can later be removed without losing the record of what it produced. A keeper matching a secret pattern is not copied and is reported. An archive is never overwritten by an older copy of the same run. The source run folder is never touched by reclaim; only `tmp/`, `cache/` and `logs-raw/` scratch inside it is, and only for runs whose every gate has passed.
- **Parallel-safe by construction.** The **main checkout is never reclaimed** — it is the user's tree and is skipped whole, always. The caller's own worktree is reclaimed only while reclaim holds its `run-lock` (a build that uses the lock cannot start meanwhile; one already running keeps reclaim out), and only caches and finished-run scratch there — never its `node_modules`. Any other linked worktree is touched only when it is **idle** (no run with an unfinished gate, no state missing, nothing written under its runs for two hours — measured on files, not folders) **and** its `run-lock` could be taken; the lock is held while deleting and released after. Anything skipped is listed as `skippedWorktrees`, so a concurrent build never has `bin/`, `obj/` or `node_modules` removed under it. Installs (`npm install`, `dotnet restore`) are Architect work and run through `run-lock.mjs` like builds, so they hold the same lock.
- **Only regenerable bytes go.** A directory is deleted only when its name is on the artifact allowlist, git tracks no file inside it, git ignores it, and it belongs to this worktree's own index — a nested repository (vendored clone, submodule) is never entered. The same proof `cleanup.mjs` uses. Anything failing it is reported as kept back, never deleted anyway.
- **Never automatic:** deleting a local or remote branch, dropping a stash, deleting a run ledger, or deleting a run folder. Those stay in `cleanup.mjs` behind `--runs` and the remote-branch authorization phrase. **Removing a worktree is not automatic in reclaim, but it is mandatory in closeout (gate 11):** only through `closeout.mjs`, which preserves uncommitted and unpushed work first. An owner-hold takes precedence over removal: apply the owner-preservation disposition, retain the open trees, record blocked closeout and audit-only commands, and report `not finished: owner hold`; never mark finished, never skip gate 11.
- **A run counts as finished only when closed**: `run-state.mjs set --gate learnings --status passed` (every tier records the learning step, with the note `nothing new` when that is the case) or `run-state.mjs finish` after acceptance. Until then its worktree, `node_modules` and scratch are off-limits to every other session's reclaim, however old the folder looks.
- Report one line per reclaim in the ledger (`freed <n>, archived <n> run(s)`), and report the run's total at the end. A reclaim error is a note, never a reason to stop the run; `--apply` failures leave the tree usable.
- The user's own periodic sweep is still `cleanup.mjs` (audit first). Reclaim never substitutes for it and never widens its permissions.

## Structured state and narrative ledger

The main checkout's run `state.json` is the structured authority for immutable scope, append-only deferrals, items and handoffs; `ledger.md` records decisions, owner card IDs and verbatim evidence paths. Both belong to the same run directory and are archived together. Use `--repo <main checkout>` for `scope`, `defer`, `item`, `handoff`, `status` and `audit`, including when working in a linked tree. Do not create a second state in a writer tree or treat a narrative summary as completion. `finish` and passing `learnings` refuse owed items/handoffs; a parked item remains listed with reason, next owner and next action. Terminal run parking retains its existing acceptance/delivery refusal and never authorizes reclaim as a passed run.


Terminal `park` and successful `finish` automatically attempt `closeout.mjs close --repo <main checkout> --run <id> --apply` after saving state and releasing its lock, from outside the closing trees. Existing safety checks retain dirty, unpushed, locked or unverified trees; run selection also refuses other unfinished owners or unreadable ownership under the tree lock (finished historical registrations do not block the current run) and preserves any `owner-hold:` block. State history records `closeout: closed|refused <reason>` without changing the terminal outcome; parked acceptance remains refused. Both explicit and implicit parking retain trees while workers are unfinished, jobs are unresolved or unreadable, or a registered tree is not idle. These extra busy checks are skipped only after successful finish; jobs-reader behavior for other callers is unchanged.

Before tree creation, `treespace.mjs room` also counts non-missing linked trees across repositories under `TRIO_HOST_ROOTS` (platform path delimiter: `:` on macOS/Linux, `;` on Windows; defaults to the main checkout's parent and `$HOME/Projects`), deduplicating repositories by the real Git common directory. The main repository's own linked trees are always included even with custom roots. At `TRIO_MAX_HOST_TREES` or above (default 12; 0 disables; invalid values use 12), rollout is warning-only by default: exit 0 with a stderr warning and a `host-tree-budget` note in JSON; `TRIO_HOST_TREES_ENFORCE=1` enables exit 2. Broken repositories are skipped with stderr notes while readable repositories are counted; if no repository is readable, `host-tree-count-unknown` also warns by default and exits 2 only with `TRIO_HOST_TREES_ENFORCE=1`. The existing free-space check still defaults to 20 GB and continues to refuse low or unmeasurable space independently of the host-budget rollout.


## Save before a terminal transition

Explicit and implicit parking, finish (including automatic learning completion), handoff records and pickup (including `--keep`) require `boundary.mjs save --run <id> --repo <main> --json` semantics before publishing state or transfer files. The save holds tree admission while the caller revalidates the state generation under a short lock; a competing transition retries once from fresh state. Preservation never grants acceptance or overrides an owner hold.

All tracked modifications and untracked non-ignored files matching the recorded scope (exact checkout-relative paths or directory prefixes at component boundaries) become one `wip(boundary)` commit on the existing task branch and a fast-forward push to its identical remote ref. The live default, primary/shared/read-only/unowned trees, secrets, active operations and unprovable remote state refuse. Missing trees require this run's closed-tree record plus proof that their HEAD remains on the live task ref.

Other untracked non-ignored files move locally, retaining relative paths and bytes, to `<main>/.trioharness-direct/runs/<id>/stray/<utc timestamp>/`. Path selection matches the canonical registered checkout and uses that run's scope; absent scope treats all untracked files as strays. The v1 no-record destination is `<main>/.trioharness-direct/stray/<sanitized branch>/<utc timestamp>/`; absent ownership still refuses mutation. The existing repository exclude must ignore the destination. Moves never overwrite existing archives; failures retain completed moves and remaining sources for retry. Each JSON checkout lists `{path, to}` in `parked`; dry-run lists prospective moves without writing. Parked files remain local for the owner after the linked tree closes, and are never pushed or deleted by this save.

`save --path <checkout> --app-owned <reservation-id>` accepts a caller attestation (at least 8 characters, path-only) only in place of a missing run registration, echoes `attested` on every checkout row (null without the flag), parks no-record strays under `.trioharness-direct/stray/<sanitized branch>/<utc timestamp>-<uuid>/`, and preserves every other refusal and dry-run restriction.
Agents write temporary files only under `.trioharness-direct/runs/<id>/tmp/`. Keep proof and logs in their dedicated run directories.

The boundary scan ignores `secret-allow.txt`: any secret-shaped hit refuses the save.
