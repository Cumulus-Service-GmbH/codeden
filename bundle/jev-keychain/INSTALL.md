# Owner install

1. Use the exact reviewed combined bundle. Keep Jev suspended until the owner install and presence verification pass.
2. Verify the staged files against the reviewed commit. Map the original paths in `baseline.sha256` to their live locations under `~/.claude/skills`, `~/.codex/skills`, and `~/.claude/hooks`. Require every live digest to match. Resolve symlinks and back up each distinct target with its permissions.
3. Compile `jev-keychain-reader.m` from the reviewed bundle with the installed macOS SDK, Objective-C ARC, Security, Foundation, and system libcurl. Sign the staged executable with hardened runtime and no entitlements using `codesign --force --sign - --options runtime --identifier com.codeden.jev-keychain-reader <staged-reader>`. Stage the build at `~/.config/trioharness/jev-keyring-runtime/bin/jev-keychain-reader` with mode `0500` and an owner-only parent directory. Record the final binary's SHA-256 and bind it to the owner card. Preserve the previous runtime directory for rollback.
4. Under the single owner install card, verify the installed reader digest. The owner grants only that binary access to the `codeden` item, account `typesafe.apiKey`, in the login Keychain. In Keychain Access, open the item without revealing its password, choose Access Control, keep the per-application access policy, add the exact installed binary to Always Allow, and save the change. The owner handles any confirmation directly. Never select Allow all applications. If the install rolls back, remove only this binary's ACL entry before restoring the previous runtime.
5. Atomically replace the backed-up files and compare every live file digest with the reviewed candidate. Stage the tests against copies of the installed files. Run the Jev and guard suites under `/tmp/codeden-suite.lock` using `node --test --test-concurrency=2`. Give Jev tests a separate home and clear the three key variables and the override file variable. Verify that the three live Jev scripts remain byte-identical.
6. Invoke the installed reader by its full path with only the `present` argument. Print `key present: yes` for exit 0 and `key present: no` for any other result. Require `yes`. A failed preflight leaves the live files untouched. A failed install verification restores the backed-up files and prior runtime state, then verifies the original digests.

The reader requires its exact installed path and a regular, owner-owned executable with one hard link and no group or other write permissions. The executable and its parent path must resolve to that same path. Run each live Jev script by its exact installed path. The presence smoke requests only item metadata, with interaction disabled before the Keychain is opened.

Jev checks the non-interactive Keychain reader first when it is installed on macOS and HOME matches the account home. A missing item, absent reader, different platform, or redirected HOME retains the documented fallback order of `TYPESAFE_API_KEY`, `TYPE_SAFE_API_KEY`, `JEV_API_KEY`, and the configured fallback file. A present item that the reader cannot access, or a failed or timed-out lookup, stops the gate with `JEV_KEYCHAIN_ACCESS_REQUIRED`. The smoke checks only metadata. Only the native transport reads the Keychain value. It posts to the fixed TypeSafe HTTPS endpoint, verifies TLS, and refuses redirects. It returns the HTTP status and checked JSON response. Tracked gates use an output-free access check before reserving an attempt. The native transport refuses to access the Keychain unless it is signed for hardened runtime without entitlements.
