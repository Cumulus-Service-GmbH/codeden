# Owner install

1. Wait for the skill-audit install to be live and for G-B to return clean high-risk reviews on the exact candidate commit. Keep Jev suspended until this install and the separate Jev-B work pass.
2. Before replacing files, verify the candidate against the reviewed commit. Map the original paths in `baseline.sha256` to their live locations under `~/.claude/skills`, `~/.codex/skills`, and `~/.claude/hooks`. Require every live digest to match the manifest. Resolve any symlinks and back up each distinct target with its permissions.
3. Provision `@napi-rs/keyring@2.1.2` under `~/.config/trioharness/jev-keyring-runtime` in an isolated staging directory. Verify that the host Node can load its `AsyncEntry` constructor without creating an entry. Preserve any previous runtime directory for rollback.
4. Under one owner install card, install the staged runtime, replace the backed-up files atomically, and compare every live file digest against the reviewed candidate. Stage the tests against copies of the newly installed files. Run the Jev and guard suites under `/tmp/codeden-suite.lock` with `node --test --test-concurrency=2`. Give Jev tests a separate home and clear the three key variables and the override file variable. Verify the three live Jev files remain byte-identical.
5. Run the presence smoke through macOS Security.framework against the login Keychain, using the generic-password service and account metadata. Disable interaction and request no password data. Print only `key present: yes` or `key present: no`, and require `yes`. A failed preflight leaves the live files untouched. A failed install verification restores the backed-up files and prior runtime state, then verifies the original digests.
